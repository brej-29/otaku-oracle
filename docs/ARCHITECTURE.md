# Architecture proposal — draft, 2026-11-06

Recommend retaining Vite for a later lightweight interface and replacing the thin Django proxy with a small TypeScript Cloudflare Worker using native `fetch`, D1 for cached metadata and atomic quota counters, and Pages for static assets and a versioned evaluation dashboard. Keep this Python/uv harness offline. This removes the need for a sleeping Python container, ORM, or database server for a public metadata tool; Django remains a sensible alternative if accounts/admin workflows become requirements. No application or UI migration is implemented in this PR, and no account was created.

Proposed request path: explicit title selection → canonical AniList ID → cache/retrieval → deterministic typed facts with record URLs → optional model explanation. Mark only directly matched metadata as verified; show explanation claims as unverified unless separately checked. Citation presence alone is insufficient. The current evaluation supplies the correct ID, so entity selection and open-ended claim checking still need separate evaluation.

Cache records by ID and schema version for 24 hours, serve stale records with their fetch time during outages, coalesce duplicate refreshes, and cache normalized title searches briefly. Use an atomic shared gate for upstream requests (maximum 25/minute across all instances), honor upstream headers, and bound the queue. Apply per-client request limits and a global daily model budget; discover zero-price `:free` models at runtime, validate configured IDs, and log the served model. Keep credentials server-side. On quota/authentication failures, open a circuit breaker and return cited deterministic facts or an explicit unknown. Publish dashboard coverage and timestamps from immutable eval artifacts; never imply a blocked run has live accuracy results.

The two existing GLBs total 21,971,316 bytes (~21 MiB). Remove them from the default load in a later UI change; use lightweight static artwork or CSS, with any retained 3D asset optional, compressed and lazy-loaded after interaction. The old Django SECRET_KEY exists in history with an insecure default; provision a new environment-only secret if Django is deployed. This PR reports that issue without reproducing the value.
